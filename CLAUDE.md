## Commands

All recipes live in the root `justfile`. Python commands run from `aifactory/` through uv.

- `just check`: full gate (frontend typecheck and vitest, pytest, mypy strict, ruff lint and format check).
- `just test [pytest args]`: frontend checks, then pytest. Single test: `just test tests/backlog/test_backlog_cli.py::test_name`, or `cd aifactory && uv run pytest tests/... -n0` to skip the frontend step and run serially.
- `just e2e`: Playwright browser test of the dashboard (uses system Chrome; `just e2e-install` installs Chromium otherwise).
- `just typecheck`, `just lint`: mypy and ruff alone. Fix formatting with `cd aifactory && uv run ruff format .`.
- `just web-test`, `just web-build`, `just web-dev` (Vite on :4701, proxies `/api` to a running `just dash`).
- `just dash`: dashboard on 127.0.0.1:4700. `just factory ...`: the CLI.
- `just bundle`: distribution ZIP in `aifactory/dist/`. `just validate`: validation scenarios in `aifactory/validation/`.

Pytest runs in parallel by default (`-n auto --dist loadgroup`). Tests marked `slow` and `browser` are assigned per file in `tests/tiers.py`. `tests/conftest.py` points `HAIFA_HOME` at a temp dir per test and fails a test that touches the real HAIFA home.

## Architecture

HAIFA is a local dashboard plus the `factory` CLI (`aifactory.cli:main`) that runs coding agents (Claude Code, Codex, pi) on backlog tasks across Git repos. A task run is: pick a backlog task, create a worktree and branch, execute a YAML workflow of agent roles and deterministic steps, then publish a PR and approve or auto-merge it.

Packages under `aifactory/src/aifactory/` and how they connect:

- `backlog/`: the backlog is a tree of markdown files with YAML front matter (`backlog/<project>/<step>/<task>.md`, each container has `index.md` with inherited defaults). `loader` only reads. Writes go through `edit` and `taskfile`, and `commit` commits them to `base`.
- `config/`: `.factory/` in a target repo. Shared files (`config.yaml`, `agents.yaml`, `roles.yaml`, `prompts/`, `workflows/`) are read from the `base` commit tree, not the working tree. `local.yaml` is machine-local and read from disk.
- `run/`: `factory task run`. Each run gets its own worktree under `<worktrees_dir>/<run-id>` and a row in `task_runs` in the trace DB (`.factory/trace.db`).
- `workflow/`: YAML workflows as data. Steps are roles from the registry or code steps (`test`, `quality`, `commit`, `changes`, `command`, `rebase`, `rebuild`), with `repeat`/`until`, `when` and `accept`. Conditions read typed envelope fields and are never evaluated as Python.
- `engine/`: agent execution ported from sssf (`vendor/sssf/templates/adws/adw_modules`). Most files are excluded from ruff and relaxed in mypy so they stay diffable against sssf. Every logic change there must be marked `# aifactory 2.9:` (or a later version).
- `harness/`: adapters for `claude | codex | pi`, registered into `engine.agents.INTERFACES`. The harness is set explicitly on the agent, never inferred from the model name.
- `providers/`: git hosting (`local`, `github` via `gh`, `azure` via `az`), chosen by `git_provider`.
- `review/`: PR publish, approve, return, resolve, auto-merge.
- `library/`, `seed/`, `onboard/`: reusable agents, workflows and skills stored in `$HAIFA_HOME`, the seed shipped in the package, and onboarding of existing repos.
- `check/`: `factory check`, read-only diagnostics split into `repo`, `machine` and `library` scopes. New rule groups are appended to `RULE_GROUPS`.
- `skill/`: `factory --skill` renders the agent skill from the argparse tree, and owns the single `--json` envelope and error codes.
- `web/`: Starlette app serving `/api/` and the built Vue app from `web/static`. The Vue source is `aifactory/web/`. `web/static` is generated by `just web-build` and is committed.
- `database/`: SQLite access, optionally via a shared database server (`just shared-db`).

## Repository conventions

- This repo is managed by HAIFA itself. `.factory/config.yaml` marks `.factory/`, `.claude/`, `CLAUDE.md`, `vendor/` and `prototype/` as protected files that runs may not change.
- Code, comments and docstrings are in English. The README and backlog tasks are in Czech.
- `prototype/` is a frozen earlier implementation. Do not change it.
