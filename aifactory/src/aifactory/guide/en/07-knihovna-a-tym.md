# Library and team

Only Git is shared: repository configuration and backlogs, and the library in its own repository. Machine settings, trace DB and keys stay local.

## Library <!-- section:knihovna -->

The library is a Git repository at `$GIRO_HOME/library` with `agents/`, `workflows/`, `skills/` and `extensions/` directories. A repository looks up items in its own `.factory/`, then the library, then the GIRO seed.

The **Library** page (library chip) has **Library contents**, **Machine check** and **Dashboard** (port) sections. Library contents offers **Synchronization** (**Pull**, **Send as PR**, open PRs), **Restore default agents and workflows**, **Import…**, and an item browser with version history and **Repositories with their own copy**: **Diff**, **Move repository copy to library** and **Delete repository copy**. Moving and deleting copies are available only here (CLI: `giro config move`, `giro config remove`).

## Changes through pull requests only <!-- section:zmeny-jen-pres-pull-request -->

Nothing is pushed directly to the library's `main`. GIRO commits every write locally (`giro library push`, `giro library seed`, import, moving a copy) and sends a PR: administrators use a branch in the library repository, others their fork. GIRO never merges or approves library PRs. Changes apply locally immediately; after merge, pull them (`giro library pull`). Check status with `giro library status --fetch`.

Administrators should configure a ruleset on `main`: require PRs with Code Owners approval and forbid force push.

## Seed <!-- section:seminko -->

The seed includes default agents, pi extensions and the `factory` skill generated by `giro --skill`. Installation and upgrades use non-destructive `giro library seed`: team modifications remain `kept`, and a dirty library is preserved with a diagnostic. Review `giro library seed --dry-run`; explicit `--take` replaces a selected item. `min_factory_version` in `library.yaml` sets the minimum GIRO version.

## New team member <!-- section:novy-clen-tymu -->

1. Install GIRO; the installer clones the default library (select another with `giro library clone <URL>`).
2. Clone team repositories and run `giro check` in each. State `installed` is sufficient; do not run `giro init`.
3. Add the repositories in the dashboard.

The first team member creates the library: `giro library init --name "Team library" --remote <empty-repository-URL>`. Install GIRO in a repository that lacks it with `giro init --dry-run`, then `giro init --commit --expect <digest>`.

## Concurrent work <!-- section:soubezna-prace -->

Run state is known only to the machine running it; everyone sees open PRs. A shared database server (`just shared-db`, address in `GIRO_DATABASE_URL`) provides a shared overview without authentication, for trusted networks only.
